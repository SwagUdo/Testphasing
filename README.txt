Попытка фазинга работы Nginx с помощью qiling и afl++

Что используется и какой версии

Nginx 1.18.0
Qiling 1.4.6
AFL++ 4.03c
UnicornAFL 0.2
Ubuntu Docker 22.04

КАК ЭТО ЗАПУСТИТЬ

1 Собрать image докера

В проекте выполнить (оно выполнит dockerfile)

docker build -t nginx-qiling-fuzz .
-t это типо название дать, можно дать любое название, главное не потеряться потом
точка в конце скажет использовать папку где находишься в терминале

2 Запустить контейнер

я не засовывал скрипты которые писал, прямо в образ, их
надо засунуть в образ вместе с запуском докера в рабочую там папку
название той рабочей папке тоже, можно свое дать, но надо учитывать
перед тем как ввести команду, перейди в папку test. cd test
или вместо pwd вводить полный адрес где сидит test

docker run -it --rm -v ${PWD}:/work nginx-qiling-fuzz /bin/bash
-i это что бы можно было писать команды в докере, по другому я не знаю как вообще с докером взаимодействовать
-t что бы был терминал
--rm это удаление контейнера, когда закончится работа с ним, лучше вообще всегда эту
фигню использовать, а то сломается что то и не починится
-v это и есть прикрепить к контейнеру -v {что то}
/bin/bash это вот контейнер завелся и он всю команду сам сделал сразу
тем самым вывев сразу командную строку
после этого проект в /work

Опциональ в контейнере можно проверить Qiling

printf 'GET / HTTP/1.1\r\nHost: fuzz\r\nConnection: close\r\n\r\n' \
| python3 /work/run_qiling.py
пусть он обычным принтом отобразит
я тут типо подписал GET / HTTP/1.1 и всякие отступы
вроде табличка наглядная вышла
вообщем эта табличка всунется с помощью | в скрипт и там уже данные по табличке выйдут
если это не важно, то можно просто python3 /work/run_qiling.py

Если все луны сошлись и всё работает, Nginx должен выдать чето типо
HTTP/1.1 200 OK

а что это значит? nginx вроде все действия свои провел и какую то
инфу выдал и это очень хорошо, потому что он это все еще и под qiling смог сделать
если тут что то не так, то я сдаюсь, можно дальше не пытатся и все переделывать

3 нужно создать типо seed, это чето типо начальных данных

начальные данные будут где то находится,
я написал здесь: mkdir -p /work/in
потом
создавай файл /work/in/seed:
printf 'GET / HTTP/1.1\r\nHost: fuzz\r\nConnection: close\r\n\r\n' \
> /work/in/seed

кароче это тупо файл где написано:
GET / HTTP/1.1
Host: fuzz
Connection: close

GET получи мне http/ и 1.1 
Host это я буду к обращению с таким то именем приходить
Connection: close - после этого закрой соединение
написано, что только такой все нормально проведет по всем этапам
но вообще можно и http/1.2 написать, он просто пройдет не всю последовательность
пути соединения, типо полетит в nginx и nginx его отклонит

это нужно AFL, он с этого все начинает, просто так его незя запустить я пытался
он будет эти данные типо менять http поменяет на tp, например или вообще
какую то случайную билиберду начнет кидать и это хорошо, что он это делает

если этого не сделать ниче вообще не будет работать

4 завести AFL++
Сначало нужно создать куда AFL будет засовывать свои результаты

rm -rf /work/out это тупо удаление папки, тут просто могут быть результаты моих потуг
mkdir -p /work/out это тупо создание папки
папка нужна чистая

тут можно установить какие то переменные
типо убрать UI export AFL_NO_UI=1
обязательно нужно выставить: export AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1
или еще чего, если надо
Запустить фаззинг:

/opt/AFLplusplus/afl-fuzz  -U  -V 300  -i /work/in  -o /work/out --  python3 /work/run_afl.py @@

/opt/AFLplusplus/afl-fuzz \тут находится сам afl
-U \ вот тут наверно я сделал что то странное
это типо unicorn mod и как я понял только так можно запустить
qiling, я хз как по другому
-V 300 \ тут можно указать работать столько то секунд
а то будет работать бесконечно
-i /work/in \ вот тут он должен взять seed типо его начальные данные
что бы процесс соединения вообще произошел
-o /work/out \  а все что он будет получать, он будет складывать сюда
-- \ это "все, больше параметров не будет"
python3 /work/run_afl.py @@ ну и запускай эту шарманку
